# 组件开发规范

## 组织与职责

通用和工作空间组件放入 `src/components/`；仅后台使用的视图放入 `src/app/(app)/admin/components/`。文件使用 kebab-case，React 组件使用 PascalCase，Props 明确类型，类型导入使用 `import type`。

新增组件前先寻找可复用实现。页面和大组件负责拼装；筛选、分页、甘特日期等纯算法放入 `lib/`，异步请求和复杂状态放入 Hook，展示组件接收 props。拆分应围绕独立职责，不以固定行数作为唯一标准。

## 服务端与客户端

- 默认沿用 Next.js 服务端边界；需要事件、状态或浏览器 API 时使用 `"use client"`。
- `window`、`localStorage`、媒体查询和浏览器事件在合适的客户端阶段访问；清理定时器、订阅与监听器。
- 不从客户端导入 `db.ts`、`data-dir.ts`、密钥处理、备份或文件系统模块。纯函数可放在无服务端依赖的 `lib/` 文件中。
- 全局用户数据与配置消费 `@/context/navelix-context`，避免复制 Provider 状态。局部表单草稿可独立维护。
- 异步请求检查响应状态，提供错误反馈；搜索与切换场景防止旧响应覆盖新状态。

## 样式与依赖

使用 Tailwind CSS 4 与现有 `globals.css` token；视觉约定见 [DESIGN](../DESIGN.md)。每次新增样式同时考虑深浅主题、窄屏、长文本和空态，不使用全局覆盖修复单点布局。

当前未引入独立 UI 组件库。优先现有原生元素、SVG 与项目工具；新增运行时依赖应说明用途、体积、许可、维护成本和服务端/客户端兼容性，并同步锁文件。不要因单个样式需求引入整套组件框架。

## 复用入口

| 场景 | 优先参考 |
| --- | --- |
| 用户数据、配置 | `navelix-provider.tsx`、`context/navelix-context.ts` |
| 标准弹窗 | `modal.tsx` |
| 既有自定义弹窗遮罩 | `overlay.tsx`，调用方负责内部结构和关闭行为 |
| 危险操作确认 | `confirm-dialog.tsx`、`use-confirm.ts` |
| 一次性消息 | `toast.tsx`、`use-toast.ts` |
| 日期与甘特计算 | `date-utils.ts`、`gantt.ts` |
| 客户端通知与埋点 | `lib/client/` |

这些文件是复用入口，不代表它们已覆盖全部边界条件。`Overlay` 仅收敛遮罩样式，不能替代完整对话框。

## 无障碍与交互验收

- 使用 `button`、`a`、表单控件等语义元素；图标按钮提供可理解的可访问名称，装饰 SVG 对辅助技术隐藏。
- 表单 Label 关联输入框，校验错误可见且可被辅助技术识别，提交时防止重复操作。
- 键盘可到达所有操作，焦点可见。对话框提供名称、适当的 dialog 语义、焦点约束、Escape 关闭与关闭后焦点恢复。
- 动态提示视需要使用 `role="status"` / `aria-live`，危险错误避免仅瞬时显示。
- 状态同时提供文字，确认对比度，不只用颜色表达逾期、失败或选中。
- 为减少动态效果的偏好提供降级，滚动区域与甘特图保持可操作。

当前 `Modal` 等已有实现仍需逐项审查这些能力；新功能不能把复用组件等同于完成无障碍验收。

## 验证与交付

为纯逻辑或业务修复增加有价值的 Node 回归测试；关键 UI 行为按需扩展 Playwright。执行相关类型和 lint 检查，界面变动检查桌面/移动及两种主题。文档与发布要求见 [DEVELOPMENT](DEVELOPMENT.md)。
