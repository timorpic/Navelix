# 全系统日志规划

状态：已实施基础能力与功能接入，资源预算和并发场景仍需持续实机压测。规划日期：2026-10-15。本文保留目标方案及实施前基线；实际支持范围、默认值和限制以 [日志中心说明](LOGGING.md) 为准。

## 1. 产品结构：按功能分类

后台入口拟为「系统设置 → 日志中心」，仅管理员可访问，桌面与移动导航使用同一配置。保留旧 `?tab=auditLogs` 地址并映射到日志中心的历史审计视图。

一级分类按产品功能组织。审计、运行、请求属于记录性质；info / warn / error 属于严重程度，均作为筛选条件，不作为一级菜单。

| 功能分类 | 子分类 | 目标事件范围 | 默认记录边界 |
| --- | --- | --- | --- |
| 账号与安全 | 登录注册、密码、会话、API Token、权限、访问防护 | 登录成功/失败、注册、退出、密码修改、会话撤销、Token 创建/撤销、账号创建/启停/删除、角色变更、CSRF/SSRF/权限拦截 | 重要安全事件完整记录；重复失败聚合；不记录密码、会话凭据、Token 值 |
| 系统管理 | 站点配置、访问策略、授权与驱动、日志管理 | 配置变更、公开访问开关、授权激活/失效、驱动加载/降级、日志配置修改、清理、导出 | 保留操作者、字段名、脱敏变更和结果；不保存授权凭据和自定义脚本正文 |
| 网址导航 | 书签、分类、快捷访问、分享、团队订阅、链接探测 | 新增/修改/删除、批量导入导出、分享创建/撤销、订阅/取消、探测批次及失败 | 成功批量操作记摘要；不逐条记录普通点击；不保存笔记、完整 URL 查询串或导入文件正文 |
| 项目与日程 | 项目、里程碑、待办、指派、日历、顺延、ICS | 创建/修改/删除、状态变更、批量写入、任务指派/取消、顺延、日历导出、版本冲突 | 记录对象 ID、字段名、状态和数量；不记录任务正文、项目描述；不逐秒记录专注时长 |
| AI 助手 | 聊天、摘要、项目拆解、日程规划、工具执行 | 请求完成/失败/取消、上游超时、工具调用、草稿保存、用户确认后的业务写入 | 记录功能、供应商/模型标识、耗时、结果、供应商返回的用量；不记录提示词、回复和密钥 |
| 通知与推送 | 站内通知、个人 Telegram、系统 Telegram | 通知创建/批量已读/删除、投递成功/失败/跳过、重试、重试耗尽、配置变更 | 正常投递记摘要；记录渠道和结果；不复制消息正文、接收地址、Bot Token |
| 备份与恢复 | 本地备份、云备份、手动/自动备份、数据库还原 | 开始/完成/失败、上传/下载、校验、还原预检、还原执行、保留清理 | 记录大小、耗时、脱敏目标、版本和结果；不记录快照内容、下载签名或存储凭据 |
| 系统运行 | 生命周期、API、数据库、后台任务、外部服务、前端、多端 | 启停/异常退出线索、迁移、数据库锁冲突、维护、慢请求、任务执行、天气/图标/更新检查、PWA/扩展请求和页面异常 | 默认记录异常、慢请求和重要状态变化；健康探测、会话刷新、实时心跳成功不逐条保存 |

归类规则：每条事件只指定一个主分类；例如账号启停归「账号与安全」，云备份定时执行归「备份与恢复」，AI 生成并确认创建项目时，AI 执行与项目写入分别记录并关联。系统运行通过关联 ID 查看这些事件，不再复制一份。

链接探测、云存储等 EE 功能只在能力实际启用时产生对应事件；日志读取与导出仍执行管理员鉴权和必要的现有功能门禁。核心日志能力规划为 CE 基础运维能力，不新增付费依赖。

## 3. 每类功能的记录力度

- 重要操作审计：安全、角色、系统策略、密钥变更、备份恢复、日志配置及清理，完整记录，不采样。
- 普通业务操作：记录对象类型、对象 ID、变更字段名和结果；批量操作一条摘要，失败项按有界数量列出，不保存正文。
- 运行诊断：默认 info，开发排障可短期开启 debug，最长 24 小时后自动恢复；始终脱敏。
- 高频读取：成功搜索、列表查询、心跳、健康检查默认不落盘。异常和慢请求记录；同类大量失败聚合次数、首次/末次时间。
- 正常定时巡检：无变化不反复记录；执行失败、恢复正常或发现异常时记录。备份等重要任务每次执行保留结果。
- 前端与扩展：后续提供受限上报，默认关闭前端上报；限制来源、频率、长度和允许字段，不上报页面内容或完整地址。

## 4. 统一事件模型

| 字段 | 含义 |
| --- | --- |
| `id`, `schemaVersion`, `timestamp` | 唯一事件 ID、格式版本、UTC 时间；界面按当前语言和时区显示 |
| `category`, `module`, `event` | 功能分类、子模块、稳定事件码，例如 `backup.cloud.upload.failed` |
| `kind`, `level`, `outcome` | 审计/业务/运行/请求；debug/info/warn/error；started/succeeded/failed/cancelled/skipped；旧记录可为 unknown |
| `actorType`, `actorId` | user/system/anonymous；已认证的用户 ID；历史账号删除不丢失事件 |
| `subjectType`, `subjectId` | 操作对象；批量操作另存数量，不复制完整对象 |
| `requestId`, `operationId`, `parentId` | HTTP 请求、跨步骤操作、父事件关联；后台任务沿用 operationId |
| `message`, `code`, `durationMs` | 安全概要、稳定错误码、耗时；文本变化不影响筛选 |
| `source`, `appVersion`, `instanceId` | web/extension/api/scheduler 等入口、应用版本、进程实例标识 |
| `details` | 按事件定义的白名单字段：变更摘要、数量、重试次数、HTTP 状态等 |

补充规则：日志严重程度和业务结果分开，用户取消不是系统错误；未完成的 started 事件不能被推断为失败。客户端传入的请求 ID 校验长度和格式，非法值重建；完整堆栈只进入受保护的诊断详情，不返回给普通用户。

投递结果需细分为 succeeded / failed / skipped / exhausted；不得直接把现有 `finished` 转成成功。历史记录无法确认结果时显示「历史结果未知」。AI 用量缺失时显示未知，不估算成实际账单。

## 5. 日志中心界面

- 左侧或顶部功能筛选：全部、账号与安全、系统管理、网址导航、项目与日程、AI 助手、通知与推送、备份与恢复、系统运行。
- 公共筛选：时间、子模块、级别、结果、操作者、来源、事件码、关键词、请求/操作 ID；默认最近 24 小时。
- 列表列：时间、功能、事件摘要、操作者、结果、耗时；详细字段放抽屉，长堆栈不撑开表格。
- 详情：脱敏变更、错误原因、关联事件与操作时间线；关联查看再次鉴权，不能凭 ID 绕过边界。
- 运行失败示例：备份与恢复 → 云备份 → 失败 → 详情 → 同一 operationId 的备份生成、上传、重试。
- 自动刷新默认关闭；开启后每 5 秒检查，页面隐藏时暂停；新事件以提示呈现，不抢走当前阅读位置。
- 导出使用当前筛选并显示范围、条数和格式；支持 JSONL，CSV 需防公式注入；单次最多 10,000 条，超出要求缩小范围。
- 日志设置独立区域：分类开关、诊断级别、保留期、容量、最近清理、写入健康状态。关键审计不能关闭。
- 保留原审计记录的独立筛选入口；不为八类功能新增八个侧栏一级菜单。
- 移动端筛选折叠、列表显示概要、详情抽屉适配；提供加载、空态、部分数据不可用、重试及键盘焦点反馈。

通知中心继续展示用户通知，日志中心提供运维事件；投递队列继续控制发送，不被日志写入替代。

## 6. 存储、查询与资源限制

延续两种存储，通过统一查询适配层按功能聚合：

1. 重要审计继续放主库 `audit_logs`，在现有字段上兼容补充分类、事件结果、关联 ID、格式版本。历史 action 映射到功能分类；无法映射归系统运行并标明旧记录，不伪造操作者、结果或 IP。
2. 普通业务摘要与运行诊断存 `data/logs/` 的 JSONL 文件，按保留等级分文件，并使用时间加分片命名，使 3/7/14/30 天的清理策略可分别执行，避免应用日常操作持续膨胀主库。控制台镜像输出同一事件 ID，采集时可以去重。
3. 文件侧建立可重建的时间范围、分类、条数与大小索引；索引是缓存，不写入业务库。首期文件分页使用有界扫描、扫描量上限和稳定游标，不承诺无限历史全文搜索；达到上限提示缩小时间范围。
4. 跨来源按 timestamp + id 稳定排序，游标绑定筛选条件和读取截止时间；已清理文件导致游标失效时明确要求刷新，不静默丢页。
5. 文件写入采用有界缓冲和批量追加；缓冲满时优先舍弃 debug / 普通 info 并计数，禁止无限增长。多进程分文件写入，轮转及清理通过租约协调。
6. logger 底层保持文件系统叶子模块，不导入 db、迁移、license；配置由上层注入并设置启动默认值，避免 EE 启动依赖环。路径沿用 `resolveDataDir()`。
7. 日志 API 只接受分类、游标、时间等结构化参数，不接受任意文件路径；固定目录内限制文件类型，禁止通过路径穿越或符号链接读取其他文件。
8. 全量 API 结束耗时在统一服务端路由包装层采集；proxy 记录自身 CSRF 拦截，不把 proxy 放行耗时误作 API 总耗时。流式请求区分首响应时间与流结束时间。

建议默认资源预算：单事件最大 16 KiB，嵌套深度和数组长度受限；缓冲总量 2 MiB；单文件 20 MiB；文件总量 200 MiB；查询每页 50 条，最大 200 条。上述为实施初始值，需用真实压力测试复核。

## 7. 保留、清理与恢复

| 数据 | 建议默认策略 | 规则 |
| --- | --- | --- |
| 关键审计 | 升级后继续保留全部历史 | 管理员可选 90/180/365 天或永久，首次缩短保留期需预览数量并确认；不静默删历史 |
| 普通业务摘要 | 30 天 | 与诊断共享总容量预算；界面提示是否因容量提前清理 |
| 运行、外部调用、请求诊断 | 14 天 | 时间或总量任一达到限制时清理最旧分片；debug 最多保留 3 天 |
| 前端错误上报 | 7 天 | 功能启用后生效，与诊断共享容量上限 |
| 个人 Telegram 投递队列 | 沿用 30 天 | 属于业务队列策略，单独于日志保留；投递事件按日志策略保留 |
| 站内通知、使用统计 | 本方案不变更 | 不因新增日志中心删除通知或上传本地统计 |
| Docker 日志 | 建议 10 MiB × 3 文件 | 显式设置驱动与轮转；具体 Compose 改动在实施阶段说明 |

清理在启动后和每日定时执行，并在轮转时检查容量；避开活跃分片，清理前取得租约。记录清理范围、数量、释放大小、原因和结果，不能触发递归清理。

容量限制只约束日志文件；永久保留的审计库单独展示占用和增长告警，不宣称整套日志受 200 MiB 硬上限约束。删除 SQLite 记录不意味着数据库文件立即变小；空间整理单独安排，不在请求中直接运行重型 VACUUM。

备份应注明：物理数据库快照含审计，不含文件日志；用户个人 JSON 导出不含系统日志。恢复前保留独立、脱敏的恢复事件和当前审计副本；还原不能覆盖当前事件历史，合并按事件 ID 去重，在临时库升级和验证后执行。新旧库结构、磁盘不足、合并失败必须有回滚及验收方案。审计副本按相同访问权限保护，受单独保留与容量说明约束。

## 8. 权限、隐私与失败处理

- 日志中心及全部查询、设置、导出、清理 API 复用 `requireAdmin()`；写操作继续经过现有 CSRF 保护。普通用户和访客不能访问全站日志。
- 不因管理员可看日志就复制个人内容：密码、Token、Cookie、Authorization、API Key、授权码、加密主密钥、消息/笔记/任务/AI 正文不得记录。
- 统一白名单序列化再脱敏，并限制错误对象、URL、嵌套字段和超长内容；不直接展开不可信对象或原始请求体。文件、控制台和导出共用安全数据。
- IP 默认不记录；排障需要时支持短期掩码记录。登录失败的用户输入标识做长度限制和不可逆摘要，不保存原始邮箱；不信任任意转发头。
- 配置差异只允许安全字段显示前后值，密钥字段统一显示「已更新」，不能用部分明文尾号代替脱敏。
- 同库关键写操作和其成功审计使用同一事务；审计失败则回滚。跨文件/网络操作用 operationId 记录阶段和最终结果，不承诺跨资源原子性。
- 普通诊断写入失败不使业务失败，降级控制台；有界统计丢失条数并显示写入异常，避免故障期间刷屏或递归调用 logger。
- 日志查询失败需显示错误或来源不完整；不能把数据库异常转换成「没有日志」。
- 启动记录上次进程正常退出标识；崩溃、OOM、强制终止不保证应用留下最终事件，排障仍需 Docker/宿主机日志。内部审计不具备对宿主机管理员的不可篡改保证。

## 9. 接口与代码落点（拟定）

- `src/lib/logging/`：事件类型、功能目录、字段白名单、脱敏、缓冲写入、轮转、查询适配和索引；不引入外部日志服务。
- `src/lib/logger.ts`：保留旧调用兼容层，逐步迁移到带 category/event 的入口；`src/lib/audit.ts` 继续负责数据库审计。
- `src/lib/daemon/`：日志清理、占用巡检；复用现有调度生命周期，异步任务防重入。
- `src/hooks/use-admin-logs.ts`：筛选、分页、取消旧请求、自动刷新；页面负责组装，组件负责展示。
- `GET /api/admin/logs`、`GET /api/admin/logs/[id]`、`GET /api/admin/logs/stats`：受限查询、详情、汇总。
- `GET/PATCH /api/admin/logs/settings`、`POST /api/admin/logs/export`、`POST /api/admin/logs/cleanup-preview`、`POST /api/admin/logs/cleanup`：管理操作；确认范围绑定服务端生成的短期预览标识。
- `/api/admin/audit-logs`：保持既有响应兼容，后续通过查询适配器复用实现。
- 可选前端上报接口单独设计认证、来源校验与速率限制；匿名登录页事件首期以服务端日志为准，不开放匿名任意写日志。

| P1：关键功能接入 | 账号与安全、系统管理、备份与恢复、通知投递、数据库与后台任务 | 成功/失败/跳过/耗尽正确区分，关键写入审计原子性验证 |

| P3：排障增强 | 可选前端/扩展上报、错误聚合、趋势、管理员 Telegram 告警 | 去重、限流、冷却、恢复通知及告警失败不递归 |

告警优先覆盖连续备份失败、迁移失败、磁盘/日志写入异常、重要任务反复失败。正常状态不重复推送；系统事件投递前复核收件人管理员身份。聚合和告警与原始记录分开，不能用聚合掩盖关键审计。
