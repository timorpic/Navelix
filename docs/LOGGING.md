# 日志中心

日志中心位于后台「系统设置 → 日志中心」，仅管理员可访问。旧 `?tab=auditLogs` 链接仍可打开审计筛选视图。日志、设置、导出与清理接口独立校验管理员身份，写请求沿用 CSRF 防护。

## 按功能查阅

| 功能 | 已接入的主要来源 |
| --- | --- |
| 账号与安全 | 登录/注册、退出、密码及资料修改、会话和 API Token、账号管理、CSRF/SSRF 拦截 |
| 系统管理 | 系统与个人配置审计、授权激活/移除、EE 加载状态、日志配置/导出/清理 |
| 网址导航 | 书签/分类工作区批量保存、链接/分享/订阅/探测接口的写入结果、外部请求异常 |
| 项目与日程 | 项目/待办领域操作、里程碑、顺延、工作区批量保存及项目/日历接口 |
| AI 助手 | 聊天/摘要/拆解/日程 API、外部调用、规则回退、工具执行/取消/确认、供应商返回的数字用量 |
| 通知与推送 | 通知 API 写入、Telegram 发送、个人投递成功/失败/跳过/重试耗尽 |
| 备份与恢复 | 备份开始/结果、本地快照复用、云端连接/上传/下载、自动备份及恢复审计 |
| 系统运行 | API 异常与慢请求、天气等外部服务、数据库维护、生命周期、可选前端错误 |

不同来源的粒度不同：领域事件提供明确动作和对象 ID；统一 API 事件提供静态接口模板、方法、状态和耗时，不读取请求或响应正文。一个成功 HTTP 响应不保证其业务内部没有发生降级，须结合关联的外部调用和领域事件查看。浏览器扩展通过已有 API 的请求记录排障，不采集扩展浏览历史。

使用功能按钮、时间预设或自定义起止时间、模块、级别、结果、记录性质、操作者 ID、来源、事件码、关键词及请求/操作 ID 筛选。默认最近 24 小时，每页默认 20 条，可选 20、50、100 条；切换条数保留筛选条件并回到第一页。分页栏显示当前页、总页数和匹配总条数；总数在应用分页游标前统计，查询不完整时明确标注为已扫描范围内的数量与页数。详情展示安全事件字段，可转到同一操作的关联记录。

自动检查默认关闭，开启后每 5 秒检查一次，页面隐藏时暂停；有新日志时提供提示，不替换正在阅读的列表。若固定了结束时间，刷新仍保持当前查询范围。

## 记录边界与隐私

记录对象 ID、字段名、数量、状态、耗时和错误码，不记录请求正文、密码、Cookie、Token、API Key、授权密钥、AI 提示词/回复、消息、笔记、任务正文或完整 URL。错误详情以稳定事件码和异常类型为主，不上传原始异常对象及堆栈；IP 不记录。配置变更仅白名单非敏感字段显示前后值。

字段白名单和长度限制在写入前执行，文件与控制台使用同一安全事件。后台对持久化内容再次校验；旧审计缺失结果显示「历史结果未知」，不从旧记录推断成功。旧投递的 `finished` 也不等同于成功。

首次随机管理员密码只写数据目录下的初始密码文件，控制台仅提示文件名，不再打印密码。数据目录和文件仍须妥善管理。

## 存储与容量

- 关键审计继续保存在 `navelix.db` 的 `audit_logs`；历史升级至 Schema v21，补充功能分类、事件 JSON 和个人投递结果，保留原字段和查询接口。
- 普通业务、运行诊断、debug 和前端事件分文件保存在 `NAVELIX_DATA_DIR/logs/`，默认数据目录为 `<cwd>/data`，Docker 为 `/app/data`。新日志使用 JSONL；文件名区分保留等级、UTC 日期和进程实例。
- 默认单分片 20 MiB，日志内容文件预算 200 MiB；缓冲 2 MiB，超过缓冲或文件预算的诊断记录丢弃并计数，控制台仍输出。多进程并发写入时预算检查存在批次级短暂偏差；索引、设置和生命周期标记是额外的小型元数据。
- 每个分片的索引包含时间范围、分类计数和大小，不包含个人正文。索引缺失、损坏或与文件大小不符时回退到有界读取，不信任索引里的路径。
- 文件查询最多扫描 32 MiB，每个文件最多读取尾部 8 MiB。达到限制、文件不可用或损坏会提示结果不完整；时间范围外的旧文件不会影响查询完整性；范围内的旧 `navelix-YYYY-MM-DD.log` 文件仅按保留策略清理，不纳入新中心全文检索。需要旧日志时从部署数据目录读取。
- 审计查询每轮最多扫描 20,000 条候选；筛选范围过大时可能提示不完整。日志中心是本地有界排障工具，不提供无限历史全文检索。
- JSONL/CSV 导出最多 10,000 条；扫描不完整或结果超限时拒绝导出，要求缩小范围。CSV 对公式起始字符进行处理。

永久审计不计入文件预算。删除数据库记录不会立即缩小 SQLite 物理文件；本功能不在请求中自动运行 VACUUM。

## 设置和清理

| 设置 | 默认值 |
| --- | --- |
| 关键审计保留 | 永久；可选 90/180/365 天 |
| 普通业务日志 | 30 天 |
| 运行/请求日志 | 14 天 |
| debug | 开关最长 24 小时，文件保留 3 天 |
| 前端错误文件 | 7 天；上报默认关闭 |
| 分类开关 | 普通日志默认全部开启；不能关闭关键数据库审计 |
| Telegram 运维告警 | 默认关闭 |

清理启动后检查，并每日定时执行；写入时也检查容量和过期分片。清理跳过近期仍活跃的文件，多个进程通过租约避免同时维护。

保存设置前会预览按新策略预计清理的审计条数及文件大小，使用绿色「确认保存」按钮；手动清理使用红色「确认清理」按钮，预览仅依据已保存策略。缩短审计保留期必须提交与当前管理员、策略匹配的短期预览凭据。保存策略允许后续定时清理；手动清理使用已经保存的策略，也必须先预览再确认，凭据只使用一次。没有符合条件的日志时显示「无需清理」及已保存策略，不发起删除；执行后显示实际删除的审计条数、文件数量和释放的文件空间。

文件与数据库是不同资源，手动清理可能部分完成；界面显示部分失败，不能视为完整回滚。日志管理操作本身写入审计。开启 debug 与缩短审计保留期同时保存时，沿用预览生成的 debug 到期时间。设置读取失败可重试；统计读取失败不会阻止设置加载或将已完成的保存、清理误报为失败。

日志设置存在受保护的 `logs/settings.json`，不属于个人 JSON 备份；迁移整个数据目录时一并迁移。损坏或缺失时回退到安全默认值。主库快照包含审计，不包含文件日志。数据库恢复在事务中保留当前审计，并按 ID 合并快照审计；重复恢复不重复插入同一事件。清理预览不从快照恢复。

## 告警与异常

启用告警后复用个人 Telegram 的系统订阅，并在投递前复核收件人管理员身份。重要迁移/存储/加密异常可首次告警，普通 error 连续三次触发，同模块冷却 30 分钟；后续成功事件触发恢复通知。通知发送异常和前端上报不会递归触发告警。聚合与冷却状态在进程内，重启后重置。

重复 warn/error 首次记录，后续一分钟内聚合；定时刷新聚合数量。审计不参与采样或聚合。不同进程各自聚合，不能当成全局精确统计。

设置页显示文件占用、审计总数、当前进程丢弃量和最近文件写入异常，以及最近 24 小时的有界事件趋势与错误聚合；它不是宿主机级健康监控。

前端上报开启后，仅已登录用户可提交白名单错误码；页面渲染错误、未处理脚本异常及 Promise 异常可记录，不接收 URL、堆栈或正文。每用户每进程限流，浏览器也限制次数。多实例不提供全局限流保证。

进程启动会检查旧生命周期标记，发现不能确认正常退出的旧进程时记录线索；OOM、SIGKILL、磁盘故障的最终原因仍需查看 Docker/宿主机日志。应用内审计不提供对宿主机管理员的防篡改保证。

## 模块组合

筛选、表格、分页为独立展示组件；`use-admin-log-explorer.ts` 组合筛选、查询、导出与详情状态，`use-admin-log-settings.ts` 管理设置与执行状态，`lib/client/admin-logs.ts` 是浏览器 HTTP 适配层。筛选模型及管理请求/响应使用明确的数据契约。

保存与清理由 `management-workflow.ts` 的版本化计划按“预览 → 确认 → 执行”组合，通过接口注入 API 和用户交互；取消、无需清理或前序失败均停止后续步骤。预览凭据不进入序列化计划与结果。全系统约定见 [模块边界与流程组合](MODULES.md)。

## 容器日志

Compose 为主应用设置 `json-file` 驱动、每文件 10 MiB、保留 3 个文件。容器输出与应用文件可能包含相同事件 ID，外部采集时可按 ID 去重。

```sh
docker compose logs --tail=100 navelix
```

直接运行源码时由终端或进程管理器管理控制台保留期。相关规划见 [LOGGING-PLAN](LOGGING-PLAN.md)，部署见 [DEPLOYMENT](DEPLOYMENT.md)。

## 历史 v20 升级兼容

历史 v2.10.13 的数据库 v20 用于其他结构调整；代码回退不会降低已部署数据库的版本号。v2.10.16 复用了该编号，部分存量实例因此缺少 `audit_logs.category`、`audit_logs.event_json`，表现为日志中心失败以及写审计时 SQL 报错。

v21 新增补偿迁移，并在每次启动的后置结构核验中幂等补齐日志字段与索引，不降低版本标记、不重建业务表、不删除审计。已经正确升级的数据库重复执行保持兼容。受影响实例应更新到包含本修复的镜像并重新创建容器，继续挂载原数据目录；单纯重启旧镜像不能补上被跳过的迁移。
