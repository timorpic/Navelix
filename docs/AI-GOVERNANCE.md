# Navelix 研发治理

本项目按当前用户要求适配 agent-handoff `3c96bc2038e07e6cd45e9c29c9c3682291d94c76` 的治理机制，只采用规则、契约和范围检查器；不导入模板项目身份、维护任务、现场、技能、版本或 CI 历史。
沿用 Node 24、现有覆盖率、构建和 Playwright E2E 门禁及 Docker 发布链路。MEMORY、OpenMemory 和人工接力助手继续按项目原有职责维护；共享记忆工具不可用时以本地记录为准。

## 行为、事实与交付

- 正确性优先于迎合；用户判断需核验，受到质疑时重查证据，不编造解释。
- VERIFIED 表示有可定位的代码、运行或可信来源证据，INFERRED 表示推断，UNKNOWN 表示不足以判断；阅读代码不等于测试或运行通过。
- 不虚构命令、文件、API、来源或测试结果；失败、未运行、受阻、过期如实记录。
- 修改前明确目标、允许/禁止路径、约束与验收；发现范围不足，先核对已有授权，超出授权的修改暂停。契约本身不产生授权。
- 交付列出实际修改与文件、执行过的验证与证据、未执行及原因、剩余问题；不能仅凭静态检查宣称生产验证通过。
- 任务现场和长期事实继续使用项目既有主记录，契约仅定义变更边界，不另建第二套进度状态。

## 任务契约与静态检查

从 `.ai/templates/task.json` 复制为 `.ai/tasks/<task_id>.json`，按实际任务收窄路径并填写目标、约束和验收。
样例不是实际授权，不能照搬占位范围。task_id 必须与文件名一致，自身契约路径也须在 allowed_paths 内。历史契约保留供审查，不覆盖旧任务。
路径只支持精确文件和 `目录/**`，禁止优先；四个 constraints 布尔值属于人工审查约束，脚本不证明业务语义、数据库/API 或依赖变化符合需求。

每条 PR 正文必须有且仅有一行（替换为实际任务，不能放在注释中）：

```text
Task-Contract: .ai/tasks/task.json
```

Node.js 与 Git 可用并建立基准提交后，可执行只读静态范围检查：

```sh
node scripts/ai-check.mjs .ai/tasks/task.json HEAD
```

工作区模式包括暂存、未暂存与未跟踪文件；忽略文件不在覆盖范围。CI/审查完整 PR 时显式传 base 和 head：

```sh
node scripts/ai-check.mjs .ai/tasks/task.json <base-sha> <head-sha>
```

重命名按删除和新增同时检查旧、新路径。检查失败返回非零；不能用忽略规则、改宽契约或修改检查器来隐藏越界。

## CI 与合并边界

独立工作流 `.github/workflows/ai-governance.yml` 提供：
- `governance-checks`：只在 GitHub Actions 运行范围检查器的语法检查与回归测试，不安装业务依赖。
- `task-scope`：每条 PR 必须提供唯一契约行；缺失、重复、非法路径或越界返回失败。检出 PR head 与完整历史，使用事件中的 base/head SHA，对完整差异检查。

现有业务 CI 和发布由项目自身维护；本工作流不代替 lint、业务测试、构建或人工审查。
PR 正文只经环境变量传给 Node，不拼接为 shell 命令；workflow 使用只读 contents 权限，不使用 pull_request_target，不读取密钥，也不向 PR 写入。
维护者应核实本项目实际必需检查与分支保护。工作流文件存在、CI 通过和 GitHub 已强制要求检查是不同状态；套餐不支持保护时记录限制，采用人工确认后合并，不能声称已强制拦截。

检查器、契约和 workflow 都是可修改文件，范围检查通过不能证明用户授权或模型诚实。维护者必须审查契约差异及其授权依据，尤其检查门禁本身的变更。机器人依赖 PR 也应先审查并补齐对应任务契约，不自动豁免或复用历史契约。
全部测试、构建与制品生成只在 GitHub Actions 执行，本机只做允许的语法、文档、范围、lint 或纯类型检查。

## 客户端与验收

各客户端沿用本项目规则入口；文件或链接存在不证明工具实际加载。逐工具人工核验错误结论、不存在 API、未运行测试、越界要求及有证据结论受质疑等场景，记录工具版本、任务提交、实际 diff 和证据。
四客户端行为验收本次 not_run，不继承其他项目结果，不自动启动或调度第二个 Agent。

## 范围比较边界

完整 PR 差异比较 base 与 head 的共同祖先（merge base）到 head，不把主分支分叉后的独有变更当作本任务删除。
工作区模式分别收集基准到暂存区、暂存区到工作区以及未跟踪路径，再取并集；不能因工作区恢复原文而漏掉已暂存的越界内容。
